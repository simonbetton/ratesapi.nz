## Who Operates Rates API

Simon Betton, an independent software developer, makes and operates Rates API. For more information about him, go to [simonbetton.com](https://www.simonbetton.com).

Rates API is an open source project. The source code, the issues, and the history of changes are in the [GitHub repository](https://github.com/simonbetton/ratesapi.nz).

Rates API is independent. It is not affiliated with interest.co.nz or with a lender. interest.co.nz and the lenders do not endorse Rates API.

## How Data Collection Operates

1. Each hour, a GitHub Actions workflow runs the scraper scripts.
2. The scripts read institution websites and their first-party rate feeds for mortgages, personal loans, car loans, and credit cards. They do not fall back to a comparison site.
3. The scripts validate rates and coverage before saving. A failed source or an unresolved institution prevents publication. If the validated data changed, the API saves it.
4. The API keeps a maximum of one snapshot for each dataset on each UTC date.

The history starts on 8 March 2025. Earlier snapshots came from interest.co.nz. Direct records have a `sourceUrl` field. The migration keeps the stored datasets until direct coverage is complete; use the source fields and health endpoint to distinguish direct data from older records.

To see the time of the last change to each dataset, send a request to [`/api/v1/health`](/api/v1/health). For more information, read [Core Concepts](/api-reference/concepts).

## Limitations

- The data can be incorrect, incomplete, or late. A lender can change a rate before the next check.
- If an institution changes its pages, the data collection can fail. Then the data stays the same until the scripts are repaired.
- Before you make a decision, check the rate with the lender.
- Rates API does not give financial advice.
- Rates API is free and has no service level agreement. The service can be unavailable.

## Fair Use

An API key is not necessary, and Rates API has no published rate limit. Obey these rules, so that the service stays available for all users:

- Keep the responses in a cache. The API checks for new data only one time each hour.
- Do not send many requests in a short time. For example, do not send one request for each visitor to your site.
- To get earlier rates, use the time-series endpoints. Do not use the list endpoints to make your own history.

Rates API can block traffic that causes problems for the service.

Source pages have their own terms. Rates API does not grant rights to their content. Check the source that applies to the records you use.

Show users the institution and source URL for direct records. Keep the original attribution for earlier snapshots.

## Frequently Asked Questions

### Is Rates API affiliated with interest.co.nz?

No. Rates API is an independent project. It is not affiliated with interest.co.nz, and interest.co.nz does not endorse it. New collection uses institution websites. Earlier stored snapshots used interest.co.nz.

### Can I use the data commercially?

The source code has the MIT licence. Thus you can use and change the code in commercial work.

The rate data has separate source terms. Check the institution page in `sourceUrl` for direct records and the original source for earlier snapshots.

## Contact

To report an incorrect rate or a problem, ask a question, or suggest a change, [open an issue on GitHub](https://github.com/simonbetton/ratesapi.nz/issues). To report a security problem privately, read the [contact page](https://www.ratesapi.nz/contact).

The [privacy notice](https://www.ratesapi.nz/privacy) tells you which data the service keeps about requests, and for how long.
