Rates API deploys two Cloudflare Workers:

| Worker | Serves |
| --- | --- |
| `ratesapi-nz` | The API routes: `/api/v1/*`, `/openapi`, and `/openapi/*` |
| `ratesapi-nz-docs` | The Fumadocs site and the routes of the docs site |

Cloudflare D1 keeps the newest datasets and the historical snapshots for the API Worker. The landing page in `apps/web` deploys to Vercel. It does not have a deploy script.

## Prerequisites

1. A [Cloudflare account](https://dash.cloudflare.com/sign-up)
2. The project, prepared for local development
3. [Bun](https://bun.sh/)
4. The [Wrangler CLI](https://developers.cloudflare.com/workers/wrangler/install-and-update/) for Cloudflare Workers and D1

## Cloudflare D1

Do these steps before you deploy the API Worker for the first time.

1. Log in to Cloudflare:

   ```bash
   wrangler login
   ```

2. Go to the API app:

   ```bash
   cd apps/api
   ```

3. Add the D1 database to your Cloudflare account:

   ```bash
   wrangler d1 create ratesapi-data
   ```

4. Copy the database ID from the output. Write it in the two `d1_databases` blocks in `apps/api/wrangler.toml`.

5. Add the tables to the remote database:

   ```bash
   wrangler d1 execute ratesapi-data --remote --file=schema.sql
   ```

> **CAUTION:** Without `--remote`, Wrangler changes only the local database on your computer.

## Worker Configuration

The configuration of the API Worker is in `apps/api/wrangler.toml`. The API Worker controls the API paths on the apex domain:

```toml
[[routes]]
pattern = "ratesapi.nz/api/v1/*"
zone_name = "ratesapi.nz"

[[routes]]
pattern = "ratesapi.nz/openapi"
zone_name = "ratesapi.nz"

[[routes]]
pattern = "ratesapi.nz/openapi/*"
zone_name = "ratesapi.nz"
```

The configuration of the docs Worker is in `apps/docs/wrangler.toml`. The docs Worker controls the apex Custom Domain:

```toml
[[routes]]
pattern = "ratesapi.nz"
custom_domain = true
```

As a result, the docs app serves `https://ratesapi.nz/`. The API Worker serves `https://ratesapi.nz/api/v1/*` and the OpenAPI routes.

## Build

Build each app in the same way as the CI build job:

```bash
bun run build
```

The API build is a Wrangler dry run. The docs build makes the OpenNext Worker bundle. The web build makes the landing page.

## Deploy

Deploy the API Worker and the docs Worker:

```bash
bun run deploy
```

To deploy one Worker only, use the name of the app:

```bash
bun run --filter api deploy
bun run --filter docs deploy
```

## GitHub Actions

| Workflow | Starts | Secrets |
| --- | --- | --- |
| Deploy to Cloudflare | On each push to `main`, or manually | `CLOUDFLARE_API_TOKEN` |
| Hourly Scraping and Database Updates | Each hour, on each push to `main`, or manually | `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` |

Each workflow runs `bun run check` before it deploys or collects data.

## After Deployment

- Make sure that `https://ratesapi.nz/` shows the docs app.
- Make sure that `https://ratesapi.nz/api/v1/health` gives a response from the API Worker.
- Make sure that `https://ratesapi.nz/openapi` shows the Scalar API client.
- Make sure that `https://ratesapi.nz/openapi/json` gives the OpenAPI document.
- Make sure that the repository has the secrets that the workflows use.

## Production Rules

- Keep the route control clear: the docs Worker controls the apex Custom Domain, and the API Worker controls the API paths.
- When you change Worker bindings or route patterns, examine the CI build job.
- Keep the OpenAPI descriptions and schemas aligned with the routes.
- Monitor scraper failures separately from Worker uptime.
